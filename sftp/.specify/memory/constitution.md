# 项目原则

## 核心价值观

### 安全第一
- 所有文件操作必须在沙箱目录内进行，防止路径穿越攻击
- 使用 SSH 密钥认证优于密码认证（生产环境）
- 敏感信息（密码、密钥）不得硬编码或提交到版本控制

### 代码质量
- 简洁优于复杂：优先使用标准库而非第三方依赖
- 错误处理必须明确，不得忽略任何错误返回值
- 代码注释需解释"为什么"而非"是什么"
- 遵循 Go 语言惯用法（effective Go）

### 性能与可靠性
- 支持并发连接，每个连接独立处理
- 实现合理的资源限制（速率、连接数、文件大小）
- 优雅处理客户端异常断开（EOF、超时、网络错误）

### 可维护性
- 配置项集中管理（常量定义）
- 日志记录关键操作和错误信息
- 代码结构清晰，职责分离（SSH 层 / SFTP 层 / 文件系统层）

## 技术约束

### 语言与工具
- Go 1.20+
- 依赖最小化，仅使用必要的标准库扩展

### 架构原则
- 单进程多 goroutine 模型
- 无状态设计，连接间互不干扰
- 文件系统操作通过接口抽象，便于测试和扩展

### 测试要求
- 核心路径映射逻辑必须有单元测试
- 速率限制器需有集成测试验证
- 文件操作安全性（路径穿越）需有专门测试用例

## 开发规范

### Git 提交
- 提交信息格式：`类型: 简短描述`（如 `fix: 修复 channel 未关闭导致客户端挂起`）
- 单次提交聚焦单一功能或修复
- 重要变更需在提交信息中说明影响范围

### 文档要求
- README 包含完整的使用说明和故障排查
- 复杂算法（如速率限制）需在 README 中详细解释原理
- 代码示例必须可运行且经过验证

### 发布流程
- 每次发布前必须运行完整测试
- 更新 README 中的版本依赖说明
- 标注已知问题和改进建议
