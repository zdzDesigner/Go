# Go MQTT Broker 代码编写指南

## 项目概述
这是一个高性能的 Go 语言 MQTT 代理实现，旨在处理 100K+ 并发连接。它使用高效的连接管理、主题路由和内存优化来实现高吞吐量。

## 构建和测试命令

### 构建
```bash
# 构建主代理服务器
go build ./cmd/server

# 构建负载测试工具
go build ./cmd/loadtest

# 构建所有二进制文件
go build ./...
```

### 测试
```bash
# 运行所有测试
go test ./...

# 以详细输出运行测试
go test -v ./...

# 运行带竞争检测的测试
go test -race ./...

# 运行特定测试文件（示例）
go test ./internal/broker -v

# 运行基准测试
go test -bench=. ./...
```

### 检查和格式化
```bash
# 格式化所有 Go 文件
go fmt ./...

# 对代码进行常见错误检查
go vet ./...

# 运行 golangci-lint（如果已安装）
golangci-lint run

# 安装检查器（如果需要）
go install golang.org/x/tools/cmd/goimports@latest
go install github.com/golangci/golangci-lint/cmd/golangci-lint@latest
```

## 代码风格约定

### 导入
- 使用空行分组导入
- 标准库导入排在前面
- 项目特定导入使用完整模块路径
- 仅在副作用情况使用空导入（如 init 函数）

```go
import (
    "context"
    "fmt"
    "net"
    
    "battery/internal/connection"
    "battery/internal/router"
)
```

### 格式化
- 使用 `go fmt` 进行一致格式化
- 保持行长度合理（建议不超过 120 字符）
- 使用空格，不用制表符
- 以 4 个空格缩进

### 命名约定
- 导出函数/类型使用驼峰命名法
- 导出常量/类型使用帕斯卡命名法
- 使用明确表明用途的描述性名称
- 避免缩写，除非被广泛认可
- 参数名为 `ctx` 表示上下文
- 参数名为 `wg` 表示同步等待组

### 类型
- 适当时候定义接口以提高可测试性
- 复杂数据实体使用结构体类型
- 基于预期用途考虑类型是否导出
- 使用命名返回值参数要适度，仅在提高可读性时

### 错误处理
- 始终检查和处理返回的错误
- 使用包装错误提供上下文：fmt.Errorf("执行 x: %w", err)
- 不要忽略错误（避免空赋值，除非有意为之）
- 适当记录带上下文的错误
- 需要时创建自定义错误类型

```go
if err != nil {
    return fmt.Errorf("连接客户端 %s 失败: %w", clientID, err)
}
```

### 并发
- 使用 sync.Map 进行并发安全映射访问
- 使用互斥锁保护共享状态
- 使用上下文进行取消和超时
- 限制 goroutine 创建以防止资源耗尽
- 可能时使用 sync.Pool 进行内存重用

### 性能
- 使用 sync.Pool 重用缓冲区以减少 GC 压力
- 在热路径中最小化内存分配
- 使用适当大小的缓冲通道
- 考虑内存布局和缓存效率

### 测试指南
- 编写表格驱动测试覆盖多种场景
- 测试正常路径和错误情况
- 使用 testify/assert 进行复杂断言（如需要）
- 保持测试快速和确定性
- 使用子测试组织相关测试用例

### 项目特定模式
- 连接管理遵循带限制的池模式
- 消息路由使用带通配符的主题匹配
- 客户端使用唯一标识符管理
- 使用上下文取消实现优雅关闭
- 由于连接数量巨大，内存优化至关重要

### Git 工作流
- 使用描述性提交消息
- 提交专注于单一责任
- 提交前运行测试：go test ./...
- 提交前格式化代码：go fmt ./...
- 需要时更新依赖：go mod tidy

### 安全考虑
- 验证来自 MQTT 客户端的输入
- 实现速率限制防止滥用
- 可用时使用安全协议
- 清理日志防止注入攻击
