# 使用设备本地续播记录

系统不建立帐号体系，也不在 server 保存匿名用户进度；H5 使用音频资源 ID 在微信设备的 `localStorage` 中保存播放位置。这样可以保持设备之间的进度隔离，避免公网匿名访问者互相覆盖进度，同时避免引入用户数据库和身份生命周期管理。

Android App 沿用设备本地续播原则，由 Media3 服务将进度写入 `SharedPreferences`，按 server 地址和音频资源 ID 隔离。后台保存不依赖 WebView 的 JS 定时器。页面返回前台时读取原生状态；冷启动只展示最后资源，点击播放后恢复。App 续播记录与微信 H5 不同步。

## Considered Options

- 按音频资源 ID 在 server 保存一份共享进度：会导致不同设备互相覆盖，不符合设备独立续播要求。
- 使用帐号保存服务端进度：能够跨设备同步，但引入了本任务明确排除的帐号体系。
