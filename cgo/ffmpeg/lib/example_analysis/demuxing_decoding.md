✦ 这个示例程序展示了 go-astiav 库的一个核心功能：解复用 (Demuxing) 和解码 (Decoding)。

  它模拟了视频播放器最基本的工作原理：读取媒体文件，并将压缩的音视频数据还原为原始的图像和声音。

  具体工作流程如下：

   1. 打开媒体文件：
       * 程序接收一个输入文件路径 (-i 参数)。
       * 使用 AllocFormatContext 和 OpenInput 打开该媒体文件，准备进行解复用。解复用就是将媒体容器（如
         MP4、MKV）拆分成独立的音频流和视频流的过程。

   2. 设置解码器：
       * 程序遍历媒体文件中的所有流。
       * 对于每个音频流或视频流，它会执行以下操作：
           1. 根据流的编解码器ID（例如 AV_CODEC_ID_H264 或 AV_CODEC_ID_AAC）查找对应的解码器 (FindDecoder)。
           2. 为该解码器分配一个上下文 (CodecContext)。
           3. 将流中的编解码器参数（如视频分辨率、音频采样率等）复制到解码器上下文中。
           4. 打开 (Open) 解码器，使其准备好处理数据。

   3. 循环解复用和解码：
       * 程序进入一个主循环，持续从输入文件中读取数据。
       * 在循环中：
           1. 解复用：调用 inputFormatContext.ReadFrame() 从文件中读取一个压缩的数据包 (Packet)。这个包要么属于视频流，要么属于音频流。
           2. 解码：
               * 将读取到的 Packet 发送 (SendPacket) 到其对应流的解码器上下文中。
               * 进入一个内部循环，调用 decCodecContext.ReceiveFrame() 来从解码器获取解码后的数据帧 (Frame)。一个 Packet
                 可能解码出零个、一个或多个 Frame。
               * 每当成功获得一个 Frame（它包含了原始的像素数据或PCM音频数据），程序就会打印一条日志，标明这是一个新的视频帧还是音频帧，
                 以及它的时间戳（PTS）。

   4. 结束：
       * 当所有数据包都被读取和处理后，循环结束，程序成功退出。

  总结：

  这个示例的功能是读取一个媒体文件，将其中的视频和音频流分离出来，并将这些流解码成原始的、可供显示的图像帧和可供播放的音频样本。它清晰
  地演示了使用 FFmpeg API 进行媒体解码的标准流程，这是构建视频播放器、视频编辑器或任何需要处理媒体内容的应用的基础步骤。
